# 设备配置（devcfg）格式规范 v1

网关采集什么设备、怎么通信、读哪些点、怎么上报，全部由一份**设备配置**描述。
现场调查表（Excel）→ 配置网页导入 → 网关保存并按配置采集；以后的上位机也读写同一种格式。

> 一台网关对应一台设备。网关出厂只烧一次固件，换设备只需重新导入配置。

## 0. 标识：devId 与 devNumber

| 标识 | 标识的对象 | 由谁设置 | 什么时候变 |
|---|---|---|---|
| `devId` 网关编号 | 网关硬件 | 出厂时用厂家账号在“出厂”页设置，印在标签上 | 换网关时变 |
| `devNumber` 设备编号 | 被采集的设备（资产） | 现场调查表，随设备配置导入 | 换网关时**不变** |

上位机按 `devNumber` 归档数据和建立设备档案，按 `devId` 管理网关（在线状态、OTA、下发配置）。
网关损坏更换时，把旧网关导出的配置导入新网关即可：devNumber 不变，数据历史连续；上位机看到同一 devNumber
换了 devId，更新绑定关系。

`devNumber` 建议规则：`<客户代码>-<设备类别>-<序号>`，如 `SN01-PLC-003`；只能包含字母、数字和 `- _ .`，
在同一个上位机系统内唯一（以后可由上位机分配）。

## 1. 文件格式：JSON Lines

每行一个 JSON 对象，用 `"t"` 区分行的种类。选 JSON Lines 而不是一个大 JSON，是因为网关内存小（无 PSRAM），
可以一行一行地接收、解析，不需要把整份配置解析成一棵树。

```
{"t":"meta", ...}       必须是第一行，一份配置一行
{"t":"device", ...}     设备，一行
{"t":"gateway", ...}    网关的上位机和网络参数，可选，一行
{"t":"point", ...}      数据点，0~256 行（协议需要点表时至少 1 行）
```

- 文件编码 UTF-8，换行 `\n` 或 `\r\n`，空行忽略，单行不超过 1000 字节，整份不超过 60 KB
- 未知字段忽略（向后兼容）；未知的 `"t"` 报错
- **写入上报报文的字段（类型标为 ascii）只能使用英文字母、数字和英文符号**（0x20~0x7E，不含双引号和反斜杠），
  避免上位机按不同编码解析时乱码；`number` 另限字母、数字和 `- _ .`。只用于显示的字段（设备名称、点名称）可用中文
- 每行可带 `"src"`（如 `"点位!12"`），表示来自 Excel 的哪个工作表哪一行，网关报错时原样带回，方便定位

## 2. meta

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schema | int | 是 | 固定 1 |
| rev | string ≤23 | 是 | 配置版本号，建议 `日期-序号`，如 `20261028-1`；上位机据此判断网关配置是否最新 |
| source | string ≤47 | 否 | 来源文件名 |
| created | string ≤19 | 否 | 生成时间 `YYYY-MM-DD hh:mm:ss` |
| library | string ≤15 | 否 | 生成时使用的协议库版本 |
| note | string ≤63 | 否 | 备注 |

## 3. device

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string ≤31 | 是 | 设备显示名称，如 `1#冲床`，可用中文；只用于网页和上位机界面，**不进报文** |
| devName | ascii ≤31 | 否 | 报文中的 devName，缺省为 number |
| number | string ≤31 | 是 | 设备编号 devNumber，见第 0 节 |
| orderName | ascii ≤31 | 否 | 报文中的 orderName |
| category | enum | 是 | `plc` / `cnc`（机床）/ `imm`（注塑机）/ `meter`（仪表，含安规测试仪）/ `board`（自研控制板）/ `legacy`（传统设备，无控制器） |
| brand | string ≤15 | 否 | 品牌 |
| model | string ≤23 | 否 | 型号 |
| protocol | enum | 是 | 协议 ID，见第 5 节 |
| iface | enum | 是 | `rs485` / `rs232` / `rs422` / `eth`，须是该协议允许的接口 |
| baud | int | 串口 | 1200~115200，缺省为协议默认值 |
| dataBits | int | 串口 | 7 / 8 |
| parity | enum | 串口 | `N` / `E` / `O` |
| stopBits | int | 串口 | 1 / 2 |
| station | int | 否 | 站号 / 从站地址 / 单元号，0~247，缺省为协议默认值 |
| ip | string | 网口 | 设备 IPv4 地址 |
| port | int | 网口 | 1~65535，缺省为协议默认值 |
| rack, slot | int | 否 | 仅 S7：机架号、槽号，缺省 0、1 |
| pollMs | int | 否 | 一轮读完所有点后的间隔，100~60000，缺省 1000 |
| report | enum | 否 | `each`（每个点单独一条报文，缺省）/ `batch`（一轮读完合并成一条批量报文） |
| devTypeId | ascii ≤31 | 否 | 上线包 / 心跳包的 devTypeId，也是上位机下发命令之前数据报文的默认值；缺省为 menuconfig 默认值 |
| devTypeName | ascii ≤11 | 否 | 上报报文的 devTypeName，缺省按协议（如 `FXPLC`） |

串口设备：网关只有一个串口，`iface` 决定拨码开关应拨的位置（`rs485` → 485，`rs232` → 232）。
`rs422` 用于三菱 FX 编程口等，需要外接 422 转换器。

## 3a. gateway（可选）

导入时写入网关的运行参数（与配置网页中修改效果相同），之后仍可在网页上单独修改；网关重启后以运行参数为准。

| 字段 | 类型 | 说明 |
|---|---|---|
| devId | string | **只用于核对**，不会修改网关编号：与本机不一致时导入前提示（更换网关时可以继续） |
| hostAddr | string | 上位机 IPv4 地址 |
| hostReportPort, hostLinkPort, hostOtaPort | int | 上位机的数据上报 / 上线心跳 / OTA 端口，0 表示不使用 |
| cmdPort, filePort | int | 本机命令端口（1~65535）/ 文件端口 |
| ethDhcp | bool | 以太网自动获取 IP |
| ethIp, ethMask, ethGateway, ethDns | string | 固定 IP 时的地址（ethDhcp 为 false 时必填，DNS 可空） |

Wi-Fi 名称和密码不放在表中（密码不宜写进文件），需要时在配置网页“设置”页填写。

## 4. point

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| fr | int | 是 | 上报编号，1~999，同一配置内唯一；报文中为 `FR001` |
| name | string ≤31 | 是 | 名称，如 `当前产量` |
| cat | enum | 否 | 分类：`state`（运行状态）/ `alarm`（报警）/ `count`（产量计数）/ `param`（工艺参数）/ `energy`（能耗）/ `other`（缺省） |
| area | string | 是 | 存储区，须是该协议支持的区，见第 5 节 |
| addr | string 或 int | 是 | 地址。按区的进制解析：三菱 X / Y 为八进制（`"17"` 即 X17），其余十进制 |
| bit | int | 位 | 字区中的位号 0~15（S7 字节区 0~7）；位区不填 |
| type | enum | 是 | `bit` / `i16` / `u16` / `i32` / `u32` / `f32` / `bcd16`，须是该区支持的类型 |
| order | enum | 否 | 32 位数据的字序：`ABCD`（高字在前）/ `CDAB`（低字在前）/ `BADC` / `DCBA`，缺省按协议 |
| scale | number | 否 | 倍率，上报值 = 原始值 × scale，缺省 1 |
| dec | int | 否 | 上报保留的小数位 0~6；缺省：f32 为 2，有 scale 时为 2，其余为 0 |
| unit | ascii ≤7 | 否 | 单位，如 `MPa`、`C`，批量报文的 ParameterUnits 使用；空为 `00` |
| mode | enum | 否 | `cycle`（每轮都报，缺省）/ `change`（值变化才报） |
| dead | number | 否 | `change` 模式的死区：变化量的绝对值超过它才报，缺省 0 |
| rw | enum | 否 | `r`（缺省）/ `rw`（上位机可写，后续版本使用） |

## 5. 协议

网关当前固件支持的协议、存储区和类型可从 `GET /api/devcfg/protocols` 读取（协议库与固件不一致时以它为准）。

| ID | 名称 | 接口 | 默认参数 | 需要点表 |
|---|---|---|---|---|
| `fx_prog` | 三菱 FX 编程口 | rs232, rs422 | 9600 7E1 | 是 |
| `fx_link` | 三菱 FX 计算机链接 | rs485, rs232 | 9600 7E1，站号 0 | 是 |
| `fx_mc` | 三菱 MC 协议（以太网） | eth | 端口 1025 | 是 |
| `hostlink` | 欧姆龙 HostLink | rs232, rs485 | 115200 8N1，单元号 0 | 是 |
| `ppi` | 西门子 PPI（S7-200） | rs485 | 9600 8E1，站号 2 | 是 |
| `s7` | 西门子 S7comm（S7-200 SMART / 1200 / 1500） | eth | 端口 102，机架 0 槽 1 | 是 |
| `modbus_rtu` | Modbus RTU | rs485, rs232 | 9600 8N1，站号 1 | 是 |
| `modbus_tcp` | Modbus TCP | eth | 端口 502，单元号 1 | 是 |
| `dbs` | DBS 真空计 | rs232 | 9600 8N1 | 否（内置模板） |
| `t76` | 76T 安规测试仪 | rs232, rs485 | 9600 8N1 | 否（内置模板） |
| `ainuo` | 艾诺安规测试仪 | rs232, rs485 | 19200 8N1 | 否（内置模板） |

三菱协议适用范围（2026-11 FX5U、L02CPU 真机验证）：
- `fx_link`：计算机链接格式 1（MC 1C 帧）。FX5U 内置 485 口设为“MC 协议”、和校验有、格式 1 已验证；
  FX3U / FX3G 需加 485-BD 等通讯板并设为计算机链接格式 1（专用协议、和校验有），协议相同但未在真机验证
- `fx_mc`：MC 3E 帧二进制，适用 FX5 系列及 Q / L 系列内置以太网，FX5U、L02CPU 已验证。
  FX5：GX Works3“对象设备连接配置设置”中添加“SLMP 连接设备”，TCP，端口须在 1024~4999 或 5010~61439（5000~5009 为系统占用），通信数据代码选二进制。
  L / Q：GX Works2“PLC 参数 → 内置以太网端口设置”，通信数据代码二进制；打开设置中协议 TCP、打开方式 MC 协议、不指定对方，
  本站端口号按十六进制填写（1025 填 0401）。L / Q 的 X / Y 为十六进制编号，本协议按 FX 的八进制解析，只有 X0~X7 / Y0~Y7 一致，
  D、M 地址上限也按 FX 设定；现场需要 Q / L 更大地址或 X / Y 8 以上时另加协议。
  **不适用 FX3 系列**：FX3U-ENET-ADP / FX3GE / FX3U-ENET-L 不支持 3E 帧

存储区（`area`）与类型：

| 协议 | 区 | 类型 |
|---|---|---|
| fx_prog | `D` | i16, u16 |
| fx_link, fx_mc | `D` | i16, u16, i32, u32, f32, bcd16 |
| | `M`, `X`, `Y` | bit |
| hostlink | `DM` | i16, u16, i32, u32, f32, bcd16, bit（需 bit） |
| | `CIO` | bit（需 bit） |
| ppi, s7 | `V` | i16, u16, i32, u32, f32, bit（需 bit 0~7） |
| | `I`, `Q`, `M` | bit（需 bit 0~7） |
| modbus_rtu, modbus_tcp | `HR`（保持寄存器 4x）, `IR`（输入寄存器 3x） | i16, u16, i32, u32, f32, bcd16, bit（需 bit） |
| | `COIL`（线圈 0x）, `DI`（离散输入 1x） | bit |

Modbus 地址为协议地址，从 0 开始（手册中的 40001 填 0）。

其他说明：

- S7：远端 TSAP = 0x01 + 机架号 × 32 + 槽号（缺省 0 机架 1 槽即 0x0101，S7-200 SMART 现场验证过；S7-1200 / 1500 需在 PLC 中允许 PUT/GET 访问）
- MC：二进制 3E 帧，X / Y 在表中按八进制写（如 X17），报文中按数值发送
- 网口设备连接状态显示在状态页“连接”（采集设备），连不上时每隔重连间隔重试
- 已在真机上按设备配置验证的协议见 `proto_lib.c` 的 `s_verified`（目前 hostlink）；导入其他协议时给出警告，不影响导入

## 5a. 现场调研表（Excel）

标准化实施的第一步：一个厂一份调研表。现场人员用离线页面 `docs/现场调研.html`（手机 / 电脑浏览器直接打开，不写入网关）
逐台点选录入并导出调研表；空白模板也可在“采集”页点“下载调研表模板”获取（下拉选项按这台网关固件实际支持的内容生成）。

现场调研页面：
- 设备名称、资产编号外各项为点选（选项少）或下拉（设备类型、控制器品牌、型号）；同型号设备“复制为新设备”
- 调研数据存 localStorage，照片与资料存 IndexedDB（按设备内部 ID 绑定）；照片压缩到长边 2048 像素 JPEG
- 设备类型（`DTYPE`，约 50 种分组列出，可手动填写）只写在调研表“设备类型”列，网关不读；
  网关用的 category 由设备类型 + 控制器品牌换算（CNC 系统 / 工控机 → cnc，弘讯 → imm，无控制器 → legacy，自研电路板 → board）
- 导出：有照片或资料时为 zip 资料包（调研表 .xlsx + `照片/`、`资料/`，文件名“资产编号-类型-序号”，“照片 / 资料”列列出文件名），否则为 .xlsx；
  .xlsx 与网关模板格式一致，“通信协议”公式同时写入计算结果，未经 Excel 保存也可直接导入网关；
  “实施状态”按调研结果给出（不采集 → 不实施，点位表可提供 → 待实施，否则待厂商资料；已上线保持）；工厂、调研人、日期写在“填写说明”第 3 行
- “打开调研资料”读回 .zip 或 .xlsx 继续修改：照片按文件名中的资产编号归回设备，实施人员填写的实施配置、采集点位、上位机与网络原样保留
- 厂商配合：“需厂商提供 / 配合”（多选 + 其他，写入调研表 need 列）与“厂商配合情况”（已提供 / 已同意 / 需付费 / 不配合 / 待沟通，help 列）；
  按控制器品牌以虚线框标出建议项（PLC → 点位表、通讯参数；数控系统 → 通讯选项授权、协议文档；工控机 → 开放数据接口、协议文档；自研控制器 → 协议文档、现场调试）；
  有配合事项且未“已提供”时实施状态为“待厂商资料”。网关导入不读这两列
- 采集点位不在本页面填写：由实施人员依据厂商点位表在 Excel 的“采集点位”表中录入
- xlsx 读写模块复制自 index.html 的 XL 模块（增加了多设备写入、设备类型列、二进制 zip），协议列表为 proto_lib.c 的快照；两者变动时同步更新该页面

| 工作表 | 谁填 | 内容 |
|---|---|---|
| 填写说明 | — | 填写步骤、地址写法、本固件支持的协议 |
| 设备清单 | 现场人员 / 厂商（左），实施人员（右） | 一行一台设备。蓝：设备信息（车间、名称、资产编号、类别、厂家、型号、联系人、能否提供资料）；绿：通讯情况（控制器品牌 / 型号、预留通讯口、现场网络、照片）；橙：采集需求（是否采集、要采什么、备注）；紫：实施配置（网关编号、点表名称、通信协议、通讯参数、站号、IP、端口、网关 IP、周期、上报方式、设备类型 ID、订单名称、实施状态） |
| 采集点位 | 实施人员（从厂商给的 PLC 点位表里挑出“需要采集的数据”对应的点抄写） | 一行一个数据：点表名称、编号、名称、地址（如 D200、DM8101、CIO100.00、V10.3、40001）、数据类型、单位、倍率、小数位、分类、上报、死区、字序 |
| 上位机与网络 | 实施人员 | 全厂共用的上位机地址、端口，固定 IP 时的掩码 / 网关 / DNS |
| 字典 | — | 隐藏：下拉列表和“控制器品牌|通讯口 → 协议”对照 |

- 资产编号即 devNumber；同型号设备在“点表名称”填同一个名称即共用一份点位（不填按资产编号对应）
- 通信协议按控制器品牌和通讯口自动带出（公式），可手动改；对照表在 index.html 的 `BRAND_PROTO` 中维护
- 导入：在“采集”页选择调研表，从列表中选这台网关采集的设备（网关编号与本机一致的自动选中），浏览器把它转换成上面的
  JSON Lines（每行带 `src`，如 `采集点位!12`）后走同样的校验和导入；表中写法有误时直接提示到行
- “导出 Excel”把当前配置导出成同样格式的调研表（一台设备）；“导出 JSONL”导出原文
- 读取 .xlsx 需要浏览器支持 DecompressionStream（Chrome / Edge 103+、Firefox 113+、Safari 16.4+）；旧版 .xls 须先另存为 .xlsx

## 6. 网关接口

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/devcfg` | 登录 | 当前配置摘要：meta、device、点数、点列表（JSON） |
| `GET /api/devcfg/file` | 厂家 | 下载当前配置原文（JSON Lines） |
| `POST /api/devcfg?check=1` | 厂家 | 只校验不保存，返回错误和警告列表 |
| `POST /api/devcfg` | 厂家 | 校验通过则保存，重启后生效；请求体为 JSON Lines 原文 |
| `POST /api/devcfg/clear` | 厂家 | 删除配置（网关停止采集） |
| `GET /api/devcfg/protocols` | 登录 | 固件支持的协议、接口、默认参数、存储区和类型 |
| `GET /api/acq` | 登录 | 实时数据：`{"running","paused","roundAge","problem","points":[[状态,值,秒前],...]}`，points 与点列表一一对应；状态 0 未读、1 正常、-1 最近一次读取失败（值为最近一次读到的值） |

校验通过返回 `{"ok":true,"summary":"...","warnings":[...]}`；校验失败返回 HTTP 400：
`{"error":"...","errors":[{"line":12,"src":"点位!12","msg":"..."}],"warnings":[...]}`，各最多 20 条。
警告不阻止导入（如网关编号不一致），由导入的人确认。

## 7. 存储

Flash 分区 `devcfg`（128 KB），分两个 64 KB 槽轮流写：先写入另一个槽，校验通过后最后写槽头（含序号和 CRC），
写到一半断电时旧配置仍然有效。保存的是导入时的原文，导出与导入完全一致。

## 8. 给上位机（后续开发）

- 上位机按 `devNumber` + `fr` 唯一识别一个数据点；`name`、`cat`、`unit`、`dec` 可直接用于界面显示和建表，不必再另行配置
- `meta.rev` 用于判断网关上的配置是否为最新；计划在上线包中带上 `rev`，上位机发现不一致时提示或下发
- 计划支持上位机通过 `POST /api/devcfg` 同样的格式远程下发配置
